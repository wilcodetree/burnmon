# BurnMon v0.2 spec

Decided in the v0.2 grill of 2026-09-22 (trail in `..\04_assets\_grill_state.md`, section
"v0.2 grill"). One release, tagged `v0.2.0`, due 2026-11-14. Two BurnMon sessions a week
from the v0.1.2 tag until release. Model routing per house rule: specs and open calls on
Fable or Opus, build sessions on Sonnet. House rules `C:\ZND\AGENTS.md`; read the trail
before changing a parser; never touch `C:\dev\Work`; stop before tagging.

## 0. TLDR

v0.2 makes BurnMon explain the burn instead of counting it, and turns the page set into
five tabs with Now as the start page. Sixteen items in five groups: store (migrations,
tool_calls), pages (five tabs, History with filters, vendor strip, Now default, English
only, owner split), insight (re-prefill, compaction, context runway, spike drawer),
forecast (live line behind a visible gate), adapters (Hermes, Copilot CLI, OTel check).
Per-vendor cost and the dev and business switch moved to v0.3, complete, with the price
book rework. Nothing in this list slips: the capacity decision was two sessions a week,
not a slip order.

## 2. Scope, by group

### 2.1 Store

S1. Migrations. A `schema_version` table; one numbered migration per step in
`internal\store\migrations\`; every migration additive (add table, add column, backfill);
the store never drops `events`. Startup runs pending migrations inside one transaction
and logs from-to versions. Test: open a v0.1 store, run to head, every v0.1 event still
present with identical ids. Replaces `store.go:101` drop-and-rebuild.

S2. `tool_calls` table and `burnmon-cli tools --since 30d --json`, as promised in the
v0.1 spec and never built. Columns: session id, turn, tool name, at, input bytes, result
bytes where the trail has them. Fed by the Claude adapter (tool_use blocks) and Codex
(`function_call` items); Hermes and Copilot write nothing here in v0.2.

S3. `burnmon-cli live` uses the same windowed query and `SessionTotals` path as the app
(`cmd\burnmon-cli\main.go:98` still loads all events).

### 2.2 Pages

P1. Five tabs: Now (default start page), History, Sessions, Tools, About. Overview,
Months, Weeks, Days and How it works go away; How it works becomes the first section of
About. Deep links `#now`, `#history`, `#sessions`, `#tools`, `#about`.

P2. History, one page. Filters at the top: period (day, week, month), range (last 7, 30,
90 days, custom), vendor (all, Claude Code, Cowork, Codex, Hermes, Copilot CLI), owner
(when rules exist, see P6). Below: totals for the filter (tokens by class, sessions,
turns, cost only where the price book covers the vendor, else "tokens only until v0.3"),
then the charts and tables of the old three pages rendered for the chosen period, one
visual per question, no duplicates. State in the URL hash so a view can be reopened.

P3. Vendor strip on Now, under the session cards. One row per vendor seen in the store,
columns today, this week, this month, tokens; total row last. Source: one SQL query
grouped by agent and period; refreshed once a minute, not per 2-second poll. Each cell
links to History with vendor and period set.

P4. Now is the start page; the last visited tab is not remembered.

P5. English only. Remove the language toggle, the `t()` table's second language, and the
`lang` setting; keep the `t()` function so copy stays in one place.

P6. Owner split, the light client map. `burnmon.json` gains an `owners` table: ordered
rules `{ "match": "C:\\dev\\Work\\*", "owner": "Valona" }`, `{ "match": "C:\\ZND\\*",
"owner": "ZND" }`, default owner "personal" when rules exist. Applied at ingest to the
session's project path, stored as one column on `sessions` (migration in S1), re-applied
to existing sessions on a rule change through `burnmon-cli reown`. Empty table (default):
one owner, no owner column shown anywhere. The full client map (per client, active time,
export) stays v0.3.

Wall rule, written here on purpose: Valona usage numbers are Wilco's to read on his own
laptop. Anything published as ZeroNonsense.dev uses aggregated ZND-side figures, or
Valona figures only with Wilco's explicit approval per fact, and never Valona substance
(project names, file paths, prompts).

### 2.3 Insight

I1. Package `internal\insight`. Input: the canonical events of one session, ordered by
turn, plus the model's context window from the price book. Output: `[]Finding{Kind,
Turn, At, Evidence map[string]float64, Cause, Confidence}`. No HTML, no store writes;
computed on request from the same windowed events the Now snapshot already loads, and
per finished session on the Sessions tab.

I2. Rules in v0.2:
- `re-prefill`: cache write in a turn exceeds 20K tokens (threshold in config). Cause
  inferred, in this order: compaction just happened (I3), model changed since previous
  turn, gap since previous turn exceeded the cache TTL, first turn after resume,
  otherwise "unknown".
- `compaction`: context size drops by more than 30 percent between consecutive turns
  while the session continues. Claude Code auto-compact threshold: VERIFY.
- `context-runway`: linear fit over the last 10 turns of context size; report turns to
  80 and 90 percent of the window. Shown on the card as "about 6 turns to 80%".
- `expensive-turn`: a turn above the 95th percentile of the session's turn cost or
  tokens, with its dominant class named.
Cache TTL for Claude Code sessions: VERIFY (5 minutes default, 1 hour extended, per the
pricing page); until verified the re-prefill cause says "gap 8 min, TTL unverified".

I3. Placement: a marker per finding on the live chart at its slot; one line in the turn
ticker; the "explain this spike" drawer on click: model, token classes, tool calls that
turn (from S2), files read, gap since previous turn, the finding's cause and confidence.
Sessions tab: findings per finished session, count by kind, click to open the turn.

### 2.4 Forecast

F1. Forecast live line on Now: the plan's line (last four weeks, weekday aware) and the
live line (current rate continued) to end of day and end of month, error band from the
scored weeks. Gate, visible: until one scored week exists the chart shows history only
with the text "forecast unlocks after the first scored week (week 46)". Scoring runs as
planned, weeks 44 to 46. Tokens only in v0.2; euros follow the v0.3 price book.

### 2.5 Adapters

A1. Hermes adapter: SQLite `messages`, WAL, 5-second poll; per-message token count;
context window VERIFY against Wilco's fixture. Fixture: one short local session recorded
by Wilco, copied to `testdata\hermes\`, personal content stripped.

A2. Copilot CLI adapter: session totals at shutdown, so the Now card says "totals at
session end" and the History page counts the session when it closes. Confirms or kills
assumption A3 (`data.db`) on Wilco's own install, not a Valona laptop. Fixture as A1.

A3. One-hour check, same week as A2: can GitHub Copilot in VS Code emit OpenTelemetry to a
local file on Wilco's laptop? Outcome written in `SESSION_LOG.md`: yes means Copilot VS
Code enters v0.3, no means the Now page stops promising it.
