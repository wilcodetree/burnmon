## F7. A new Codex session appears only after "Refresh now"

Evidence: at 14:12 a Codex CLI session ("Work", turn 1, 13K tokens, model unknown) had no
card while the page polled every 2 seconds; it appeared the moment Wilco pressed Refresh
now, which runs `a.rebuild` (full rescan). So the events were readable, and the live
watcher never ingested that rollout. The same session had two older Codex cards live, so
the watcher works for files it already knows.
Hypotheses, in order, confirm on disk before changing anything:
1. `handleFsnotifyEvent` (`internal\watch\watch.go:182`) gets a `Create` for the new
   rollout, calls `onChange`, and the ingest path drops it because the file is not yet in
   the cursor table or `RootsByAdapter` does not resolve a brand-new path. Log the path
   and the adapter chosen on every `onChange`.
2. Codex writes the rollout to a temp name and renames it; `Rename` is filtered out at
   `watch.go:183` and the later `Write` events go to a path the watcher never saw. Log
   raw `ev.Op` for every event under the Codex root for one live session.
3. The rollout lives under a folder created after startup (a new day folder), the `Create`
   for the folder arrived, `addTree` ran, but the file `Create` inside it fired before the
   watch was added. Compare timestamps in the log.
Fix whichever hypothesis holds. Test: create a temp Codex root, start the watcher, create
a new day folder and a new rollout file with one `session_meta` and one `token_count`
line, assert the snapshot shows the session within 2 seconds. Write the confirmed cause
and the measured latency in `SESSION_LOG.md`.

## F8. The running chart jumps

Evidence: Wilco's report; `drawNowChart` (`internal\report\template.html:1380`) destroys
and rebuilds the Chart.js instance every poll, and both axis maxima are recomputed from
the current window's raw peak (`:1389`). Replaces v0.1.1 F3's rule "Y max recomputed per
poll, holds the scale until the spike leaves the window".
Fix, decided (grill, question 12):
- One Chart.js instance for the life of the page; each poll sets `data` and calls
  `update()` with the default animation (about 300 ms). Sessions that appear or
  disappear between polls are diffed by session id into the dataset array.
- The x axis is a time axis with `min = now - 30 min`, `max = now`, moved every poll.
  So the picture drifts 2 seconds left per poll; the rightmost 10-second slot grows
  until it closes and a new empty slot opens at the edge. Slots stay 10 seconds, 180 per
  window, dense, as F3 built them.
- Y max (tokens) and right-axis max (cost): `smoothedMax = max(peak * 1.1,
  smoothedMax * 0.95)` per poll. It grows instantly to a new peak and decays 5 percent
  per poll after the peak leaves the window. Never below a floor of 10K tokens.
- Tick labels: one per 5 minutes on round minutes, so only the edge label changes.
Check: 5 minutes of watching with a Codex and a Claude session running, no visible jump
in either axis, no full redraw. `node --check` on the template JS as in F3.
