# BurnMon v0.2.3 patch: check the real window, then fix (2026-09-23)

Runs before V3-1. Model: Sonnet. Tag `v0.2.3`.

## Why this patch exists

v0.2.1 and v0.2.2 were both verified by proxy: no session could see or click the WebView2
window. Wilco's review after v0.2.2 (2026-09-23, around 12:55, three screenshots) shows the
proxy checks missed real defects. So item W0 comes first: a way for a session to drive
the real window. No item counts as done until W0's harness has checked it.

## Items

W0. Real-window harness, dev only. WebView2 honours the environment variable
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`. Add
`tools\uicheck` (Go, `chromedp` with a remote allocator on that port, no Node). It
attaches to a running `burnmon.exe`, and per check takes a screenshot into
`testdata\uicheck\out\` (git-ignored), reads the DOM, clicks and presses keys. The port
opens only when the variable is set by hand; release builds and README never set it, so
the "no ports" promise holds for users. Add `scripts\uicheck.ps1` that starts the exe with
the variable, waits for the page, runs the checks and stops the exe. Every item below gets
one check in it.

W1. Startup shows nothing. The window is white and "Not Responding" until the first
collection ends. Cause to confirm: work on the UI thread before `w.Run()` in
`cmd\burnmon\main.go` (store open and migrations, `SeedNativeRoots`, `startLiveWatch`
registering watches). Fix: the window shows a startup page at once, all startup work runs
in a goroutine, and the page shows the current step (opening store, migrating, scanning
sources, reading files x of y, building the page) with a spinner. Check: screenshot within
1 second of launch shows the startup page, and the title never reads "Not Responding".

W2. The turn drawer still cannot be closed. v0.2.2 made `bmTurn` async and added Esc; it
still fails. Find the cause with the harness (does the click reach `closeTurnDrawer`, does
something reopen the drawer, is the UI thread blocked). Check: open a drawer from a bar and
from a ticker line, close it with the X, with an overlay click and with Esc, and confirm
the overlay is gone in the DOM and on the screenshot each time.

W3. The drawer has a horizontal scrollbar. Wrap long paths in the tool-call table and the
files-read list; no horizontal scroll at the drawer's 560 px width. Vertical scroll only
when the content is taller than the window.

W4. Duplicate legend items. The legend shows "recent session" twice and
"claude-code · claude-sonnet-5 · burnmon" twice: datasets are added, not diffed by session
id. Fix: one dataset per session, updated in place. Replace "recent session" with a real
label (project, else the first 8 characters of the session id).

W5. Legend order: vendor, then client type (CLI, desktop, VS Code), then model, then
project, alphabetical inside each level. The cost item stays last.

W6. Left axis labels repeat ("3M, 3M, 2M, 2M, 1M, 1M") because `tok()` rounds. Axis ticks
and tooltips on this chart use two decimals: `1.25M`, `850.00K` (`K` below one million,
`B` from one billion). Other uses of `tok()` on the page stay as they are.

W7. Every minute gets its time label on the X axis (`12:31`, `12:32`, ...), none skipped.
Font 11 px; rotate labels 45 degrees only when the chart is narrower than 36 px per
minute. This replaces v0.2.2's "every 5 minutes under 40 px" rule.

W8. The right (cost) axis disappears while the cost series is hidden, and returns when it
is shown. The legend toggle drives it. Hidden by default.
