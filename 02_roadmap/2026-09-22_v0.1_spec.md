# BurnMon v0.1 spec

Target 2026-10-17 (plan rows week 40 to 42, `2026-09-22_burnmon_plan.md`). Built in Claude
Code sessions on Sonnet, in the order below; each step ends with a passing build, a passing
`go test ./...`, a semver tag, and one line in `SESSION_LOG.md`. Judgment calls that this
spec does not settle go back to Wilco as a question, not a guess.

Baseline: v0.0.1 (commit `3d00f22`), a straight rename of claudecost. Module `burnmon`,
`go 1.25.0`, `cmd\burnmon` (WebView2 app), `cmd\burnmon-cli`, `internal\{scan,dataset,agg,
pricing,report}`, one HTML template `internal\report\template.html`, dedup rule "one entry
per requestId, largest output_tokens wins" (`internal\scan\parse.go`). The app renders the
report to a file and calls `Navigate(fileURL)`; JS calls back through `w.Bind` (`ccRefresh`,
`ccSaveSettings`). No open ports, no network, `asInvoker`. Keep all of that.

## Step 1. Schema and store (week 40)

**Goal.** Every parsed turn becomes one `Event` in one schema and lands in a local SQLite
file; the existing dashboard reproduces its numbers from the store, not from a rescan.

**Schema**, new package `internal\schema`:

```go
type Event struct {
    Vendor      string    // "anthropic", "openai", "github", "nous"
    Agent       string    // "claude-code", "cowork", "codex", "copilot-cli", "hermes"
    Surface     string    // "cli", "vscode", "desktop", "unknown"
    SessionID   string
    RequestID   string    // dedup key together with Vendor; Codex: session id + turn index
    ParentID    string    // Claude subagent's parent session id, else ""
    At          time.Time // UTC
    Model       string
    Project     string    // cwd or repo path as the trail gives it, "" if unknown
    Input       int64     // fresh input
    CacheWrite  *int64    // nil when the vendor has no such class
    CacheRead   *int64
    Output      int64
    Reasoning   *int64
    VendorCost  *float64  // Hermes records real cost; nil otherwise
    WindowUsed  *float64  // Codex rate_limits used_percent (5h) when present
    WindowReset *time.Time
    Tools       map[string]int64 // tool calls in this turn, Claude only for now
}
```

**Store**, new package `internal\store`, driver `modernc.org/sqlite` (pure Go, no cgo; the
one new dependency this step). Tables: `events` (all fields above, unique index on
`(vendor, request_id)`, insert with "largest output wins" upsert to keep the dedup rule),
`cursors` (`path`, `offset`, `mtime`, `size`) so each trail file is read from where it
stopped, `meta` (schema version, app version, price-book date). File at
`%LOCALAPPDATA%\burnmon\burnmon.db` (same folder rule as the cache today; macOS and Linux
equivalents via `os.UserConfigDir`). The gob parse cache is removed once the store
reproduces its numbers.

**Adapter interface**, new package `internal\adapter`:

```go
type Adapter interface {
    Name() string                          // "claude", "codex", ...
    Roots() []string                       // folders to watch, from the existing scan discovery
    Parse(path string, from int64) ([]schema.Event, int64, error) // events since offset, new offset
}
```

Move the Claude and Cowork parsing from `internal\scan\parse.go` behind
`internal\adapter\claude`, emitting `Event`s; keep `scan.go` and `wsl.go` for discovery.
`internal\agg` and `internal\dataset` read from the store and build the same `Payload`.

**Tool usage, added 2026-09-22 (hub decision, feeds the public `audit-my-context` skill).**
The `Tools` map already on `Event` is normalised into its own table, `tool_calls`
(`vendor`, `request_id`, `tool`, `kind`, `count`), where `kind` is one of `builtin`,
`mcp-tool` (name `mcp__<server>__<tool>`, server derivable), `skill` (from a `Skill` tool_use's
`input.skill`, or a `Read` of a path ending in `SKILL.md`, name = parent folder), `agent`
(`Agent` tool_use's `subagent_type`). New CLI verb `burnmon-cli.exe tools --since 30d --json`
prints, per tool, server, skill and agent: invocations, distinct sessions, first and last seen,
split by agent (`claude-code`, `cowork`) and by project. Output shape matches
`C:\ZND\projects\znd-skills\skills\audit-my-context\scripts\collect-usage.ps1` so the skill
reads either. No token figures per tool in v0.1: schemas are deferred and not in the trail.
Excluded project fragments from the existing config apply here too, so walled trees never
appear. Adds one table and one verb to this step; the Done-when gains "`tools --json` on the
fixture trail returns the counts in `testdata\tools_expected.json`".

**Done when.** `burnmon-cli.exe report` from the store equals the v0.0.1 report for the
same two months (diff the JSON payload, zero differences except the schema meta). `go test
./...` has a test per adapter with a fixture trail under `testdata\`. Tag `v0.1.0-alpha.1`.

## Step 2. Codex adapter (week 41)

**Source.** `%USERPROFILE%\.codex\sessions\YYYY\MM\DD\rollout-<ts>-<uuid>.jsonl`, or
`$CODEX_HOME\sessions` when set; on Windows also the WSL distros' `~/.codex/sessions`
through the existing WSL discovery. Facts and VERIFY tags:
`..\04_assets\2026-09-22_token_monitor_sources_and_facts.md`, section B.

**Parsing rules.**
- A line is `{"type":"event_msg","payload":{"type":"token_count", ...}}`. Read
  `payload.info.last_token_usage` (`input_tokens`, `cached_input_tokens`, `output_tokens`,
  `reasoning_output_tokens`) for the turn and `payload.info.total_token_usage` as the
  running total. Counters are cumulative per session: if `last_token_usage` is absent,
  derive the turn as the delta of `total_token_usage` against the previous event.
- Model: the most recent `turn_context` event before the token count (`payload.model`).
  If the field name differs on a live file, read the file and adapt; do not guess.
- Fresh input for the schema is `input_tokens - cached_input_tokens`; `CacheRead` is
  `cached_input_tokens`; `CacheWrite` is nil (Codex has no such class); `Reasoning` is
  `reasoning_output_tokens`.
- `payload.rate_limits.primary.used_percent` and `resets_at` (or the names found on the live
  file) fill `WindowUsed` and `WindowReset`.
- `RequestID` = `<session uuid>:<turn index>`; `Surface` from the `session_meta` line's
  `originator` if present (`codex_cli_rs`, `codex_vscode`, else "unknown"). `Project` from
  `session_meta.cwd`.
- Files can be huge (openai/codex issue #24948: 700 MB to 2 GB); read from the cursor
  offset, never whole-file. A `.jsonl.zst` sibling, if found, is logged and skipped in v0.1.

**Pricing.** New price-book entries for OpenAI models in `internal\pricing`: the model
ids seen on Wilco's laptop first, list prices from developers.openai.com/codex/pricing and
the rate card, dated inside the JSON. Cached input is priced at the cached rate. Unknown
model: price as 0 and count it under "unpriced" in the payload so the dashboard shows it.

**Done when.** Wilco's own Codex sessions appear in the store with the right model, turn
count, tokens and cost; a fixture trail under `testdata\codex\` with three turns and one
`rate_limits` object passes a table test. `price-check` CLI command prints every book with
its date. Tag `v0.1.0-alpha.2`.

## Step 3. The Now page (week 42)

**Goal.** The first page shows what is happening now: running sessions, their context
fill, a live burn chart. Source of truth for the design:
`..\04_assets\2026-09-22_burnmon_now_page_features.md`, sections 2 and 3. This step
implements the minimum in the plan's "done when"; the cache clock and the turn ticker are
in scope only if the week allows.

**Ingest, live.** New package `internal\watch`: `fsnotify` (second new dependency) on every
adapter root; on a write event, call `Parse(path, cursor)` and upsert. WSL roots are polled
every 5 s instead (inotify does not cross the boundary; ASSUMED, confirm on the laptop and
note the result in `SESSION_LOG.md`). The 15-minute full rescan stays as a safety net.

**Transport to the page.** No server, no port. The page polls a bound Go function
`bmLive()` every 2 s; it returns a JSON snapshot: running sessions (trail changed in the
last 10 minutes; constant `runningWindow`, configurable in `burnmon.json`), per session:
agent, surface, model, project, start, last turn, turn count, context size of the last turn
(`Input + CacheRead + CacheWrite`, or `Input + CacheRead` for Codex), context window for
the model, tokens this session, cost in the active price mode, cache hit ratio of the last
turn, subagents under their parent; plus the last 30 minutes of per-minute buckets
(tokens by class, cost) per session. The CLI gets `burnmon-cli.exe live --json` printing
the same snapshot once, for tests and for a later TUI.

**Context windows.** A new table in the price book JSON, `context_window` per model id,
dated. Fill it during the session from platform.claude.com/docs/en/about-claude/models and
developers.openai.com/codex (model pages); VERIFY tag in the JSON comment field. Unknown
window: gauge shows tokens only, no percentage.

**Page.** A new first tab "Now" in `template.html`, the existing tabs unchanged behind it.
Layout: session cards in a row (agent icon as text badge, model, project basename, context
gauge as a horizontal bar with 60, 80, 90% colour bands, tokens, cost, last turn "12 s
ago"); under it the live chart (Chart.js, already vendored: stacked bars per minute by
session, cost as a line on the right axis, 30-minute window, re-drawn on each poll); under
that a placeholder card "Forecast: needs one scored week, showing history" that renders the
last 7 days per day from the store. Dev mode only in v0.1; the switch is v0.2. Empty
state: "No running sessions. Start Claude Code or Codex and this page fills within two
seconds."

**Done when.** With Claude Code and Codex both running on Wilco's laptop, the Now page shows
both sessions with a context percentage and the chart moves within 2 seconds of a turn;
`burnmon-cli.exe live --json` prints the same sessions; a test feeds a fixture append to a
temp trail and asserts the snapshot changes. Build passes `.\build.ps1`. Tag `v0.1.0`.

## Rules for the building session

- House rules from `C:\ZND\AGENTS.md`: no em dashes anywhere, full `C:\ZND\...` paths in
  prose, semver bump per step, one `SESSION_LOG.md` paragraph per session.
- Read a trail file before writing a parser for it. Field names in this spec that carry
  "or the names found" are to be confirmed on disk first.
- Never scan `C:\dev\Work` or any Valona folder. Adapter roots are the developer's own
  home folders only.
- A question the spec does not answer goes to Wilco with two or three candidate answers
  and a recommendation, then the session waits.
- Commit and push are Wilco's; the session stops at a green build with the tag command
  printed, not run.
