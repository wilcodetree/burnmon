## 2. Scope, by group

### 2.1 Cost

C1. Price books, dated JSON, built into the binary, overridable in `burnmon.json`. Three
kinds: API list price per vendor and model (Anthropic and OpenAI exist in
`internal\pricing\pricing.go`, re-dated after a live check); plan credits where the vendor
publishes a table (GitHub Copilot AI credits; ChatGPT or Codex credits VERIFY); subscription
share (the existing claudecost config block). Hermes and any vendor without a book:
"tokens only". `burnmon-cli price-check` prints every book with its date and source URL.

C2. Per-vendor cost. Each event gets cost on all three bases where a book covers it,
computed on read, never stored. The headline per vendor is the basis that matches the
configured plan: credits for Copilot, subscription share when configured, else API list
labelled "upper bound". The other two sit one click away. One Go function serves Now,
History, Sessions and export, so the numbers agree everywhere.

C3. Dev and business switch, per `..\04_assets\2026-09-22_burnmon_now_page_features.md`
section 4. One toggle in the header, dev by default; `"mode": "business"` in
`burnmon.json` sets the start state (Talon's config). Dev shows tokens, context, cache.
Business shows euros on the headline basis, credits left where known, client, and the
forecast in euros. The switch flips every number on the Now page.

### 2.2 Clients

K1. Client map. Each `owners` rule gains optional `client` and optional `remote` (a git
remote URL pattern). Match order per session: rule whose `remote` matches the project's
git remote (read from `.git\config`, no git binary), then rule whose `match` path matches,
then owner default with client "unassigned". Migration 6 adds `client` on `sessions`.
`burnmon-cli reown` re-applies both. A v0.2 `burnmon.json` stays valid unchanged.

K2. Active time. Per session: sum of gaps between consecutive events, a gap over
`active_idle_minutes` (default 10) counts zero. Per client: sum of its sessions. Label
everywhere: "active time, from transcript timestamps, not billable". Spot-check against
Wilco's own time log once, result in `SESSION_LOG.md` (plan assumption A8).

K3. Client view. History gains a client filter next to owner. In business mode History
shows a per-client table: tokens, headline cost, active time, sessions. Sessions tab gains
a client column. All hidden while no client rule exists.

K4. Export. `burnmon-cli export --since <date> --until <date> --owner <name>...
--label <name> --out <file>`. JSON with `schema`, `label` (default `dev-1`, never the
hostname), `exported_at`, `price_book_dates`, and rows of day, owner, client, vendor,
model, five token classes, cost on each basis present, active minutes. No paths, no
session ids, no prompts, no project names beyond the client name. When owner rules exist,
`--owner` is required, so a Valona row never leaves by accident.

K5. Merge. `burnmon-cli merge <file>... --out <dir>` writes `merged.json` and a static
`report.html` (no scripts from the network, opens offline): one column per input label,
totals per client, vendor and week. No cap. Refuses files with a different `schema`.

### 2.3 Adapter

A4. Copilot in VS Code, `internal\adapter\copilotvsc`. Tails the OTel file the two VS Code
settings produce (A3, 2026-09-23), 5-second poll like Hermes, last write wins per request.
Tokens and model per request from the `gen_ai.*` span attributes; project from a workspace
attribute where present, else unassigned. README shows the settings. Fixture: Wilco's
real 476 KB span file, stripped of prompt text, in `testdata\copilotvsc\`.

### 2.4 Platforms

B1. GitHub Actions job builds `burnmon` and `burnmon-cli` for darwin and linux (amd64,
arm64) with `CGO_ENABLED=0`. Off Windows the app opens its page in the default browser
(the existing fallback), WebView2 stays Windows-only behind its build tag. Default roots
for Claude, Codex, Hermes and Copilot on macOS and Linux. README and About say "untested
on macOS and Linux". Release artefacts attached to the tag.

### 2.5 Now page and monitor mode (added 2026-09-23, after v0.2.3)

U1. The Now page intro ("Running Claude Code, Cowork and Codex sessions, live. Polls every
2 seconds...") moves to About. The "No running sessions" notice moves under the live burn
chart as one small line, not a panel above it.

U2. Loading state. Until the first data arrives, every visual (chart, session cards,
vendor strip, forecast) shows a spinner or skeleton with "Loading...". The page must not
show "only available in the BurnMon app window" while the app's bound functions are still
being injected: retry until they exist, and show that text only in a saved report. The
vendor strip was seen empty after startup (header, no rows): find why and fix it. An empty
axis reads "0", not "0.00K".

U3. Monitor mode. A second view that fills the window with three panels only: live burn
chart, running sessions, vendor strip. No header, no tab bar; one small switch "Full view"
brings the normal page back. The last choice is remembered in `burnmon.json` (`"view":
"monitor"` or `"full"`) and the settings dialog sets the default. Business mode shows
monitor mode with the normal visuals and euros.

U4. Monitor mode in dev mode is real text: a monospace, dark terminal page. The chart is
drawn with block characters (one column per minute, one row set per session, vendor
colours from v0.2.2), sessions and the vendor strip are text boxes with ASCII borders.
No hover or bar click; a session box opens the turn drawer for its last turn. Same 2-second
poll, no extra backend calls.
