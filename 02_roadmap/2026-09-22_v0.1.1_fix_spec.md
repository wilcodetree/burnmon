# BurnMon v0.1.1 fix spec

Source: Wilco's first live run of v0.1 (commit `693ea5a`) on 2026-09-22 with a Claude Code
Sonnet session, a Codex `gpt-5.6-sol` session and a Cowork Fable session running at the
same time, plus a perfadvisor screenshot of the same minute. Six findings, ordered by
damage (F2 was rewritten at 12:44 when the Codex cards did appear). Each has the evidence, the reading of the code as of `693ea5a`, and the fix.
Where the code reading is a hypothesis, the session confirms it on disk before changing
anything and writes what it found in `SESSION_LOG.md`.

## F1. burnmon.exe used 1,886 MB and the machine thrashed (fix first)

Evidence: perfadvisor top line "memory thrashing: 17158 hard faults/s at 96% RAM, top:
burnmon.exe 1886 MB".
Code: `cmd\burnmon\main.go:289`, the `bmLive` binding calls `st.AllEvents()` on every
2-second poll and `live.BuildSnapshot` groups the whole history in memory each time.
Fix: add `store.EventsSince(from time.Time)` (indexed on `at`) and
`store.SessionTotals(sessionIDs)` (SQL `SUM` per session for tokens and cost inputs);
`BuildSnapshot` takes the last `chartWindow` of events plus the running sessions' totals,
never the full table. Add an `at` index if missing. Measure: with the store Wilco has today,
`bmLive` must stay under 50 MB working-set growth over 10 minutes of polling (log the
runtime `HeapAlloc` every 30 polls at debug level). Also check `UpsertEvents` on a 2 GB
Codex rollout does not read the file whole: `Parse` seeks to the cursor, good, but confirm
the first pass over an existing huge file streams and commits in batches of 1,000 events.

## F2. Codex arrived minutes late, and its cards say UNKNOWN

Evidence: at 12:29 and again at 12:42 local the running Codex `gpt-5.6-sol` session had no
card and no series; at 12:44 two Codex cards were there (`gpt-5.6-sol`, 16 turns, 904K
tokens, 65K of 400K context, and a second one labelled `codex-auto-review`, 1 turn, "context
window unknown"), with surface "UNKNOWN" on both and the rollout filename as the legend
label. So the adapter works; the ingest was late by minutes, not the 2 seconds the spec
promises, and two labels are wrong.
Diagnostic for the latency, run once with a Codex turn finishing while you watch the log:
1. Is the Codex root on the fsnotify path or on the 5-second poll path? Print which at
   startup.
2. Does `watch.go:153` receive a `Create` for a new day folder and then `Write` events for
   the rollout inside it, or do Codex writes only surface at the 15-minute rescan? Log the
   time between the rollout's mtime change and the `UpsertEvents` call; the number goes in
   `SESSION_LOG.md`.
3. Was the first pass over Wilco's existing Codex history (many large rollouts) still
   running, so the live event queued behind it? If so, the first pass must run in the
   background and live files must be served first: two goroutines, live watcher ahead of
   the backfill.
Fix whichever step 1 to 3 shows, with a test that appends one `token_count` line to a temp
rollout and asserts the snapshot changes within 2 seconds.
Labels: (a) `classifySurface` (`codex.go:101`) does not recognise the `originator` value
Codex 11.12.1 writes; read it from the live `session_meta` line and map it (`codex_cli_rs`
to "cli", the VS Code value to "vscode", the Desktop value to "desktop"), keep "unknown"
only for a value never seen and log it once. (b) `codex-auto-review` is not a model: it is
the rollout's `originator` or a sub-run name landing in the model field; show it as the
session title and leave the model empty when the trail has none, "context window unknown"
stays honest.

## F3. The chart is not a running chart

Evidence: labels 10:05, 10:06, 10:08, 10:09, 10:10, 10:13: minutes without turns are
skipped, bars are category columns, the window does not slide, and at 12:29 local time the
axis says 10:38 (UTC labels, `live.go:245` formats `e.At.UTC()`).
Fix, the perfadvisor model ("history, newest right", fixed width, own-peak scale):
- Fixed window of 30 minutes, 10-second buckets, 180 slots, every slot present, zero when
  empty. The x axis is a time axis in local time; the newest slot is at the right edge and
  the whole chart shifts left every poll.
- One stacked series per running or recently running session, colour by session, label
  "agent · model · project basename", never the raw uuid (uuid in the tooltip).
- Cost per bucket as a line on the right axis, scaled to its own peak in the window.
- Class split inside a bar (fresh, cache write, cache read, output) only in the tooltip
  in v0.1.1; a per-class toggle is v0.2.
- The snapshot carries `window_start`, `bucket_seconds` and a dense array; the page
  never derives slots from sparse data.
- Y axis max is the window's peak, re-computed per poll, so a spike keeps the scale until
  it leaves the window, as perfadvisor does.

## F4. Cowork is labelled CLAUDE-CODE

Evidence: the Cowork card reads "CLAUDE-CODE · DESKTOP". `claude.go:292` and `:326` set
`Agent: "claude-code"` for every transcript and only `Surface` distinguishes.
Fix: `Agent = "cowork"` when `classifySurface` says desktop or cowork, `"claude-code"`
otherwise; the card then reads "COWORK · DESKTOP" and "CLAUDE-CODE · CLI". Regression test
on the existing fixtures. The report's "By surface" table is unaffected.

## F5. Fable shows 285K of 200K (100 percent)

Evidence: the Cowork card gauge is full and orange at "285K / 200K tokens (100%)".
Cause: `context_window` in the price book has 200,000 for `claude-fable-5-1`, or falls
back to it. Fix: read the window from platform.claude.com/docs/en/about-claude/models for
every Claude model id seen in the store and for the OpenAI ids, date the table
(`ContextWindowBookDate`), and never clamp: when context exceeds the table, the gauge
shows the raw number, a grey bar and the text "window in book: 200K, exceeded, check
book date", because a wrong book must be visible, not hidden by a 100 percent cap.

## F6. Header copy is still claudecost

Evidence: "Your share of what we actually pay for Claude" under the BurnMon title, and
"Running Claude Code and Codex sessions" above the cards while Cowork is also shown.
Fix: subtitle "What your coding agents burn, live and by month"; Now-page lead "Running
Claude Code, Cowork and Codex sessions, live." The README pass stays in a later week.
