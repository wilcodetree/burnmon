# BurnMon v0.2.1 patch: the window hangs on Refresh (2026-09-23)

Runs before V3-1. Model: Sonnet. Measure first, then fix. Tag `v0.2.1`.

## Symptom (Wilco, 2026-09-23 11:03)

Title bar "BurnMon (Not Responding)" after Refresh now. perfadvisor at the same moment:
`burnmon.exe` 98.5% CPU, 1,438 MB, 175 MB/s disk. Three live sessions (Cowork, Claude
Code, Codex). Laptop at 87% RAM, CPU throttled to 69%.

## Hypotheses, from reading the code (not measured)

H1. The UI thread waits on the database. `internal\store\store.go:47` sets
`SetMaxOpenConns(1)` and no WAL mode. `jchv/go-webview2` runs bound functions (`bmLive`
every 2 s, `bmVendorStrip` and `bmForecast` every minute) on the WebView2 UI thread.
`rebuild` runs in a goroutine, but holds the one connection for the whole ingest and
`AllEvents`. Every poll blocks behind it, so the window freezes.

H2. `rebuild` still runs the v0.1 pipeline. `Collect` in `internal\dataset\dataset.go`
loads `AllEvents()`, rebuilds sessions and months, weeks and days, and `report.Render`
embeds that payload in `dashboard.html`, then the page reloads. The Overview tab is gone
since 40B. This is the likely source of the 1.4 GB and most of the CPU.

H3. The 175 MB/s disk read is unexplained. Candidates: SQLite page reads on a large
`events` table with no WAL, a live Codex rollout re-read from offset 0, or the WSL walk
(`rebuild(true)` on Refresh).

H4. `bmHistory` calls `AllEvents()` on the UI thread on every filter change.
